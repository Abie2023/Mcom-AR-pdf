# Fund Report Parser

Streamlit application that fetches a Morningstar fund report by Document ID, extracts relevant content locally with PyMuPDF, sends only the compact context to Gemini, and exports a Morningstar-compatible Excel workbook.

## Workflow

```text
Morningstar Document ID
    -> in-memory Morningstar PDF download
    -> PyMuPDF page/text/table extraction
    -> scanned-PDF detection and relevant-page selection
    -> compact local context
    -> selected Gemini model
    -> JSON validation
    -> Morningstar 19-column Excel output
```

The PDF is never saved to disk. Text and tables are extracted locally before the Gemini request. The existing extraction prompt, JSON structure, holding classification, and Morningstar output mapping are preserved.

## Requirements

- Python 3.9 or newer
- Internet access for Morningstar and Gemini requests
- A Gemini API key

Dependencies are listed in `requirements.txt`:

```text
streamlit
pandas
openpyxl
openai
PyMuPDF
requests
python-dotenv
```

## Setup

Create and activate a virtual environment, then install dependencies:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Configure the Gemini key with either method:

### `.env`

```powershell
Copy-Item .env.example .env
notepad .env
```

Set the value in `.env`:

```text
GEMINI_API_KEY=your_key_here
```

`.env` is ignored by Git. Never put a real key in `.env.example`.

### Streamlit Secrets

Create `.streamlit/secrets.toml` locally:

```toml
GEMINI_API_KEY = "your_key_here"
```

The app checks `st.secrets["GEMINI_API_KEY"]` first and falls back to `GEMINI_API_KEY` loaded from `.env`.

## Run

```powershell
streamlit run app.py
```

In the app:

1. Enter a numeric Morningstar Document ID, such as `670134091`.
2. Enter the target fund name and portfolio date in the sidebar.
3. Use `Refresh Gemini Models` to discover compatible models for the configured key.
4. Select a Gemini model. `gemini-3.8-flash` is the default fallback model.
5. Click `Process Report`.
6. Review the extracted table and download the generated Excel workbook.

## Gemini model selection

The app queries the Gemini Models API and keeps only preferred models that advertise `generateContent` and pass an access/capability check. The preferred list is:

- `gemini-3.8-flash`
- `gemini-3.7-flash`
- `gemini-3.6-flash`
- `gemini-3.5-flash`
- `gemini-3.5-flash-lite`
- `gemini-3.1-flash-lite`

Model discovery is not treated as a guarantee of successful extraction. A selected model is used for one normal request; transient 503/network failures have bounded retry behavior. A 404 reports that the model is unavailable for the API key and does not automatically try another model.

## Error handling and diagnostics

The UI reports the selected model, request count, input character count, estimated input tokens, PDF page counts, relevant pages, vision pages, and response time. Gemini failures include the model, status code when available, concise API information, and retry guidance.

## Output

The workbook is generated in memory and contains one worksheet named `Sheet1` with the existing Morningstar 19-column schema, including:

- Portfolio Date
- Fund Id
- Fund Name
- Holding Id
- Holding Name
- Number of Share
- Market Value
- Coupon Rate
- Maturity Date
- Portfolio Currency (Base)
- Fund TNA

The remaining template columns are preserved in their existing order.

## Morningstar URL configuration

The application constructs the URL from the numeric Document ID and the configured Morningstar URL constants. The fixed `clientid` and `key` values are part of the supplied Morningstar document URL pattern; they are separate from the Gemini API key and are not used for authentication to Gemini.

## Repository safety

The repository ignores `.env`, `.env.*`, `.venv/`, and `__pycache__/`. `.env.example` is intentionally limited to:

```text
GEMINI_API_KEY=
```

Do not commit API keys, `.env`, Streamlit secrets, generated bytecode, or downloaded PDFs.
